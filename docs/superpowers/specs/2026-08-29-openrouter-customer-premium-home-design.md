# OpenRouter 主题首页精致科技感重构设计（2026-08-29）

## 背景

当前交互 Demo 已具备完整首页、二级页面、三级模型详情和 Mock 交互，但首页视觉被用户判定为“不够美观”。问题不在 Customer 色系本身，而在视觉语言仍然接近通用 SaaS 模板：标题过重、留白缺少视觉锚点、四张等宽卡片过于机械，卡内图形也更像占位插画而不是模型路由产品。

本轮只重做设计原型，不修改 `web/customer/` 基线，不实现正式 `web/openrouter/` 主题，也不连接真实接口。

## 方案比较与决策

评估过三个方向：

1. **极简大气**：最大化标题与留白，减少卡片和装饰。优点是接近 OpenRouter 的气质，缺点是容易再次显得空而普通。
2. **精致科技感**：保留 OpenRouter 的首屏信息结构，引入 Kiro 式精密线条和微型数据界面，并完全使用 Customer 色系。优点是兼顾品牌感、产品真实性和视觉记忆点。
3. **产品化稳重**：弱化营销表达，向 Customer 控制台靠拢。优点是清晰可靠，缺点是首页品牌张力不足。

用户已选择第 2 个方向。设计组合为：**OpenRouter 的大气结构 + Kiro 的精致细节 + Customer 的完整色系**。

## 硬约束

- 颜色以 `web/customer/src/styles/tokens.css` 中的 `--customer-*` 为唯一来源，覆盖页面背景、面板、强/弱文字、边框、Hover、Focus、品牌绿、蓝色、Warning、Danger、圆角和阴影；不得为微型图表或健康状态新增任意色值。
- 深色只允许用于代码示例和唯一的高反差快速接入区，使用 Customer 中性深色，不引入暗色主题。
- 保留现有首页、模型目录、动态模型详情、排行榜、Pricing、Docs、Console Overview 和 API Keys 路由。
- 保留搜索、筛选、排序、模型对比、成本估算、Mock Key 创建、命令搜索、键盘和移动端交互。
- 不加入 Chat Playground。
- 不复制 OpenRouter 的 Logo、插画、品牌素材或文案，只参考信息层级。
- 不修改 `web/customer/`，不替换现有 Customer 色值或资产。

## 设计主张

首页的记忆点不是一组卡片，而是一条贯穿首屏与能力区的“模型路由轨迹”。轨迹从 Hero 中央的统一 API 节点出发，连接提供商、实时性能和权限策略，使所有视觉元素都表达真实产品概念，而不是装饰。

桌面端轨迹是一条视觉连续的细线：从 Hero 统一 API 节点向下穿过指标轨道，并在能力区分叉连接四张能力卡。平板端拆为 Hero、指标和能力区三个光学对齐的线段；移动端退化为 Hero 内的单条垂直连接线，不跨卡片绘制，避免裁切和页面级横向溢出。

页面只保留一个强视觉动作：路由轨迹在首屏进入时完成一次连接，随后静止。其余交互只使用轻微边框、阴影和位移反馈。

## 首页结构

### 1. 顶部导航

- 保留品牌、模型、排行榜、价格、文档和控制台入口；“服务正常”继续作为不可点击的只读状态标记，不新增状态路由。
- 搜索缩短为紧凑命令入口，避免占用过多首屏横向空间。
- 当前路由通过浅绿底和底部细线表达，不使用大面积胶囊。
- 移动端保留品牌标记、搜索和菜单三个入口。

### 2. Hero

- 继续使用居中布局，但减少标题字重和字符挤压，桌面标题控制在 64–72px，移动端控制在 40–46px。
- 主标题保持一眼可读的两段关系：“一个接口”与“连接所有模型”，仅第二段使用深绿强调。
- 副标题限制在两行内，取消额外下划线和英文装饰标签堆叠。
- 双 CTA 保留“创建 API Key”和“发现模型”，按钮宽度与肩线对齐。
- Hero 背后加入极淡的路由坐标场：一个统一 API 节点连接 4–6 个模型节点，使用细线、数据标记和轻量渐隐，不使用发光球、玻璃拟态或彩色光斑。

### 3. 指标轨道

- 四项指标仍位于 Hero 下方，但不再作为四个孤立大数字。
- 指标沿一条细线轨道排列，每项由主数值、短标签和一个状态点组成。
- 使用等宽数字，并降低数值尺寸，让指标成为路由视觉的一部分。

### 4. 四项能力

能力区仍紧接指标区，但改为两行错落的 12 列编排，而不是四张完全相同的竖卡：

- **统一模型接入（5 列）**：提供商节点、模态标签和统一请求入口。
- **高可用路由（7 列）**：展示真实感更强的路由决策表，包含模型、提供商、延迟和健康状态。
- **价格与性能（7 列）**：展示紧凑模型比较表和小型趋势线，而不是抽象折线插画。
- **数据与权限（5 列）**：展示 Key 作用域、预算和数据策略开关的 Mock 界面。

四项能力使用不同的信息密度和内部构图，但共享同一边框、圆角和排版规则。卡片标题与正文全部使用中文，英文仅作为真实模型标识、API 字段或数据单位出现。

四卡的唯一交互分别固定为：统一模型接入进入 `#/models`，高可用路由进入 `#/rankings`，价格与性能进入 `#/pricing`，数据与权限进入 `#/console/keys`。卡内的状态、预算、作用域和策略控件均为只读 Mock 展示，不表现为可操作开关；只有明确的卡片行动按钮可聚焦和点击。

### 5. 热门模型

- 保留四个可进入三级详情的热门模型。
- 从厚重卡片改为轻量横向模型条目：提供商标记、模型名、上下文、输入/输出价格和趋势在同一阅读线上。
- 桌面端四列，平板两列，移动端固定为单列；不得隐藏价格字段或引入页面级横向滚动。

### 6. 快速接入

- 使用全页唯一的深色中性区形成节奏反差。
- 左侧说明“一次集成，随时切换模型”，右侧保留真实可复制的 OpenAI SDK 示例。
- 不提供在线输入、请求发送或 Playground 功能。

## 排版、形状与材质

- 标题使用系统中文无衬线字体，降低过度字重；数据和 API 标识使用等宽字体。
- 面板圆角保持 14–18px，按钮与输入框保持 9–12px，不使用过量胶囊形状。
- 静态面板使用一层细边框和极轻阴影；Hover 只增加边框清晰度与 2px 上移。
- 网格纹理仅用于局部数据界面，不再覆盖四张能力卡的全部视觉区。
- 不使用多色渐变、玻璃拟态、霓虹光、随机浮动气泡或通用机器人插画。

## 动效

- 每次进入并完成渲染 `#/home` 时，路由轨迹播放一次 600–900ms 的连接动画，随后静止；从其他 SPA 路由返回首页时允许重新播放，但不得循环。
- 模型状态点可使用低频透明度呼吸，但不得持续移动布局。
- 卡片 Hover 使用 160–180ms 的边框、阴影和位移过渡。
- `prefers-reduced-motion: reduce` 下路由轨迹直接显示最终状态，关闭所有非必要动画。

## 响应式

- `>= 1180px`：能力区采用 5/7 与 7/5 错落布局。
- `768–1179px`：能力区改为稳定的 2×2 网格，内部数据界面保持可读。
- `< 768px`：Hero 单列，双 CTA 全宽，指标为 2×2，能力区单列。
- `390px` 下标题不得出现单字孤行，所有交互目标至少 44px，不产生横向溢出。

## 原型交互与数据流

- 所有数据继续使用内存中的 Mock 数据，不调用后端。
- `data-route` 仍是页面导航的统一入口；首页四项能力依次进入模型目录、排行榜、Pricing 和 API Keys。
- 热门模型保留可聚焦的详情入口，并按模型 slug 渲染对应三级页面。
- 首页不再依赖旧的循环路由定时器；路由动画节点不存在时不得启动定时器。
- 未知 Hash 继续规范化到 `#/home`。

## 异常与降级

- 原型不产生真实网络错误；复制失败时继续使用现有 Toast 显示待复制内容。
- 缺少动画节点时页面静态显示，不抛异常。
- 小屏无法完整呈现复杂微型表格时，保留关键字段并将次要字段换行，不直接隐藏业务含义。
- 无动画偏好、键盘操作和移动菜单继续沿用现有可访问性行为。

## 验证与验收

- JavaScript 语法检查通过。
- `git diff --check` 或等价的空白检查通过。
- 不存在 `fetch`、XHR、Axios、WebSocket 或 Playground 文案与功能。
- 桌面 `1440px`、平板 `768px`、移动 `390px` 截图检查无裁切、横向溢出或标题孤行。
- 首页 CTA、导航、能力入口、热门模型、二级页面和三级页面路由可用。
- 逐项冒烟验证模型搜索、提供商/能力/上下文筛选、排序、视图切换、最多三个模型对比、成本估算、排行榜周期切换、Mock Key 创建与搜索、命令搜索、复制反馈、键盘进入模型详情、弹窗焦点恢复和移动菜单。
- 首页、Pricing 和模型详情在浏览器中保持 Customer 色系，控制台无新增错误。
- 主按钮、正文和辅助文字对比度满足可读性要求。

## 非目标

- 本轮不实现正式 React 主题代码。
- 不修改后端、数据库、计费、认证或部署配置。
- 不改变 Customer 主题的现有颜色、功能、路由或数据。
- 不在原型中加入真实 API 调用、持久化或生产密钥。
