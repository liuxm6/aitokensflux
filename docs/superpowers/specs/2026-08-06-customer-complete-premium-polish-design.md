# Customer 全链路保留式高端精修设计（2026-08-06）

## 背景与目标

本轮覆盖 Customer 前端的完整用户链路：公开首页、认证与配置引导、充值与订阅，以及登录后的全部控制台页面。

用户选择的方向是“保留现网高端感，提升排版、间距、层级、材质和一致性”。本轮不换皮、不重构业务，不改变颜色体系、品牌资产、路由、接口、权限或业务流程，而是建立统一视觉秩序并消除跨页面的不一致、拥挤、闪动和布局跳变。

## 硬约束

### 必须保留

- `web/customer/` 当前浅色纸感、翡翠绿品牌点缀、中性色表面、语义状态色、渐变、边框、阴影和品牌资产。
- 首页全屏 Hero、动态模型轮播、双 CTA、福利卡、能力区、价格与套餐区块顺序。
- 所有现有路由、路由别名、导航顺序、登录判断、权限边界和数据来源。
- 充值、套餐购买、支付方式、余额支付、订单进度、用量、密钥、邀请、设置等全部现有流程和字段。
- 所有加载、错误、空状态、键盘行为、焦点恢复、移动导航和 Dialog 行为。

### 允许调整

- 排版层级、字号和行高。
- 页面及区块间距、面板内边距、对齐和内容密度。
- 响应式布局、换行规则、表格窄屏表达和移动端安全区。
- 焦点可见性、触控目标、错误关联和其他不改变业务语义的可访问性细节。
- 不改变现有色值和功能的轻量动效、尺寸稳定性和布局跳变修复。

## 统一视觉系统

### 排版层级

- 页面主标题、区块标题、面板标题、正文、辅助信息和标签形成稳定的六级层级。
- 首页保留宽松、大字号和低密度；控制台采用更紧凑的同源层级，不另建视觉语言。
- 金额、额度、用量、Token 数和费率在对应页面使用等宽数字，避免数值变化引发布局抖动。
- 长标题和多语言文案允许自然换行，不通过缩小到不可读字号解决溢出。

### 间距与容器

- 桌面页面边距、内容最大宽度、区块纵向节奏和 Panel 内边距使用统一标尺。
- 移动端减少无效留白，但保持标题、正文和主操作之间的清晰层级。
- 相同类型 Panel、摘要卡、筛选器和表格在不同页面保持一致的标题区、内容区和操作区结构。

### 共享组件

优先统一以下共享表面，页面只增加必要的作用域覆盖：

- `ConsolePageHeader`
- `Panel`
- `ConsoleSummary`
- `DataTable`
- `AsyncState`、`EmptyState`
- `Dialog`、确认 Dialog、购买和充值 Dialog
- `FormField`、输入框、选择器和操作按钮
- 分页、筛选器、状态标签和金额摘要

## 公开页面

### 首页

- 保留现有 Hero 高度、氛围背景和模型轮播，继续校准视觉中心、标题基线、双按钮肩线和首屏留白。
- 能力区保持轻量四列，不改为通用 SaaS 卡片阵列。
- 模型价格区保持 sticky 表头、等宽数字和现有交互；保证加载、错误、空数据和滚动时尺寸稳定。
- 套餐与按量充值区强化价格、权益、支付入口的阅读顺序，同时保持现有卡片颜色和购买流程。
- 支持渠道、FAQ 和 Footer 使用统一的触控目标、展开动效、链接节奏和移动端布局。

### 登录、注册与密码重置

- 统一表单宽度、字段间距、标签、辅助文字、错误提示和提交区。
- 第三方登录、Passkey、验证码和邀请码保持现有流程，只改善分组与扫描顺序。
- 移动端使用动态视口和安全区，确保软键盘出现时当前字段与主按钮可见。
- 错误反馈与字段通过可访问属性关联，首个错误字段自动获得焦点的现有行为必须保留。

### 配置引导及其他公开页面

- Setup 向导统一步骤标题、说明、代码块和主次操作层级。
- OAuth、协议、隐私、Not Found 等页面复用公开页面容器和排版标尺。
- 不改变配置内容、回调行为、外链目标或认证跳转。

## 充值与订阅

### 信息架构

充值和购买界面的固定阅读顺序为：

1. 当前余额或套餐状态。
2. 金额或套餐选择。
3. 支付方式。
4. 应付摘要与必要说明。
5. 唯一主操作。

### 充值与购买 Dialog

- `TopupDialog`、`PlanPurchaseDialog` 和购买进度 Dialog 使用一致的宽度、标题区、滚动区和底部操作区。
- 金额预设、自定义金额、支付方式和余额支付保持全部现有选项与校验逻辑。
- 选中、禁用、加载、失败和处理中状态不能只依赖颜色表达。
- Dialog 在移动端使用动态视口高度；内容滚动时关闭按钮和最终确认操作保持可达。
- 请求进行中时保持现有防重复提交和禁止关闭规则。

### Subscription 与 Billing

- Subscription 统一套餐卡、当前套餐摘要、按量充值入口和购买按钮的视觉层级。
- Billing 页面统一记录筛选、表格、分页、类型、金额、状态和参考号表达。
- 移动端记录转换为结构化卡片，但不得隐藏桌面端已有字段。
- 套餐与按量充值的展示差异必须清楚，但不能改变业务分类或排序规则。

## 登录后控制台

### 外壳与导航

- 侧边栏、顶部栏、账户菜单和页面内容使用统一高度、间距和触控目标。
- 保持现有导航项、顺序、路由和移动端开关逻辑。
- 页面切换时背景与内容容器保持稳定，避免懒加载造成明显闪动。

### Dashboard

- 优先展示当前套餐、余额、用量和关键操作。
- 保持现有数据和按钮，不重复创建相同入口。
- 当前套餐、可选套餐、钱包和教程卡形成清晰主次关系。

### Usage

- 筛选器、统计摘要、数据表格和分页形成固定结构。
- 长模型名、请求详情、延迟、Token 和费用信息在不同宽度下保持可读。
- 移动端记录卡必须保留时间、类型、模型、延迟、Token、费用和详情字段。

### API Key

- 强化密钥名称、掩码、分组、额度、过期时间和操作之间的关系。
- 保持创建、复制、编辑、删除、确认和 CC Switch 相关流程不变。
- 窄屏下操作按钮完整可见，不依赖横向溢出隐藏功能。

### Invite

- 邀请码、邀请链接、奖励摘要、记录筛选和分页使用统一数据页结构。
- 复制反馈继续使用现有 Toast，不增加独立反馈系统。

### Settings

- 账户、安全、偏好、集成等现有内容按视觉层级分组，不改变字段、顺序或行为。
- 只读信息、普通操作和危险操作必须在层级上可区分，但保持现有颜色体系。

### 其他登录后页面

- Setup、Subscription、ATF Switch Connect 等页面复用统一页面标题、Panel、表单和操作区规则。
- 不修改连接协议、回调地址、外部工具配置或数据写入行为。

## 响应式策略

统一验证以下视口：

- `375px`：单列移动端、软键盘和安全区。
- `768px`：平板与窄屏控制台。
- `900px`：侧边栏和复杂表格的临界布局。
- `1280px`：标准桌面。

规则：

- 所有可点击元素触控目标至少 `44px`。
- 不通过隐藏字段解决窄屏拥挤；表格按内容类型转换为记录卡。
- 筛选器和操作区按优先级换行，主操作保持明确。
- Dialog 不超出动态视口，必要时仅内容区滚动。
- 页面和区块不得产生无意义横向滚动。

## 动效与稳定性

- 页面加载、异步状态和 Dialog 仅使用克制的透明度、位移或经明确批准的内容展开动效。
- FAQ 等内容展开允许使用 intrinsic-size 或 grid-track 高度过渡。
- 价格列表、筛选器、分页和异步状态切换不得导致不必要的整体布局跳动。
- 页面懒加载期间保持外壳和背景稳定，避免二级页面背景闪动。
- `prefers-reduced-motion: reduce` 下停止所有非必要动画和过渡。
- 不新增持续重绘、高成本模糊或影响滚动性能的视觉效果。

## 可访问性

- 每页只有一个明确主标题，标题层级连续。
- 键盘顺序与视觉顺序一致；所有交互都有可见焦点。
- Dialog 保持焦点锁定、Esc 行为和关闭后的焦点恢复。
- 表单标签、说明和错误信息通过语义属性关联。
- 金额、状态、错误和选中状态不能仅依赖颜色。
- 装饰图标不进入无障碍名称；有意义的图标必须提供名称或文本。

## 实施分区

虽然作为一个整体项目交付，实施仍按以下顺序保持每步可测试和可回滚：

1. 全局标尺与共享组件。
2. 充值、订阅和购买 Dialog。
3. 控制台外壳与 Dashboard。
4. Usage、Billing、Token、Invite、Settings 等数据页。
5. 首页、认证、Setup 和其他公开页面。
6. 全链路响应式、动效、可访问性和视觉收口。

任何阶段都不得以未完成状态破坏现有页面。

## 验证与验收

### 自动化

- 为每个修复先增加能够失败的回归测试。
- 运行 `bun test`。
- 运行 `bun run typecheck`。
- 运行 `bun run format:check`。
- 运行 `bun run build`。
- 运行 `git diff --check`。

### 浏览器走查

- 对 `375 / 768 / 900 / 1280px` 进行关键页面截图核对。
- 检查首页、登录注册、Dashboard、Subscription、Billing、Usage、Token、Invite 和 Settings。
- 走查充值、套餐购买、余额支付、处理中、成功与错误路径。
- 检查键盘导航、焦点恢复、移动端菜单、Dialog、复制反馈和 reduced-motion。
- 浏览器控制台不得出现新增错误或警告。

### 最终审核

- Standards 审核：确认符合 `AGENTS.md`，无未授权颜色、功能或跨页面污染。
- Spec 审核：逐项确认本规格全部实现，无缺失、错误实现或范围扩张。
- 未通过双轴审核不得进入发布流程。

## 非目标

- 不改变后端接口、数据库、计费、支付或权限逻辑。
- 不新增路由、支付方式、套餐、字段或业务流程。
- 不替换品牌、配色、Logo、插画或营销文案语义。
- 不重写现有 Customer 前端架构，也不引入新的 UI 框架。
- 不在本设计阶段提交生产发布。
