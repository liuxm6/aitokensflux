# OpenRouter 主题「请求剖面」交互 Demo 设计（v8）

## 背景

现有 v7 Demo 已具备完整页面、Customer Emerald 色系和主要 Mock 交互，但首页仍然更像常规 SaaS 营销模板：主张与产品卡片左右分栏、相似数据在多个章节重复出现、页面节奏长期一致，并且没有形成 TokenFlux 独占的视觉记忆。

本轮基于 OpenRouter、Vercel、Linear、Stripe、Raycast、Anthropic / Claude 等热门开发者网站重新审视首页。用户已从三个方向中选择并确认 **A「请求剖面」**：页面本身就是一次请求从进入、归一化、评分、选路到建立备用路径的工程剖面。

本轮只制作新的交互 Demo，不修改正式主题代码。

## 已确认的设计目标

- 首屏不再使用“左侧文案 + 右侧大型产品卡片”的常见结构。
- 在一个桌面视口内同时完成产品主张、双 CTA、策略选择、候选评分、主路由、备用路径和选择理由。
- 把请求路径、分叉和故障切换塑造成 TokenFlux 的品牌母题，而不是装饰线。
- 首页按证据阶梯展开，每个章节只回答一个问题，不重复同一组卖点。
- 页面总长度比 v7 缩短约三分之一。
- 保留所有二级、三级页面、路由、字段、Mock 数据和既有交互。
- 保留 Customer 的完整浅色 Emerald 系统，不引入新的品牌色。
- 不加入 Chat Playground、真实请求、真实 API Key 或后端连接。

## 非目标

- 不实现正式 React 主题。
- 不修改 `web/customer/` 或 `web/openrouter/`。
- 不修改后端、数据库、Docker、CI/CD 或生产发布配置。
- 不修改 PostgreSQL 或任何真实数据。
- 不删除、隐藏或替换现有二级、三级页面能力。
- 不接入真实模型、真实价格、生产监控或外部资源。
- 不构建聊天输入、发送消息或响应流式输出能力。

## 受众与体验目标

主要受众：

- 正在比较多模型网关的开发者。
- 关注成本、延迟和稳定性的技术负责人。
- 需要快速判断平台可信度的技术采购者。

用户进入首页后应在十秒内理解：

1. TokenFlux 接收统一格式的请求。
2. TokenFlux 会根据策略为候选模型评分。
3. 每次选择都有清楚的主路由、备用路径和原因。
4. 用户可以继续查看模型、价格、排行、文档和 API Key。

## 对标原则

- **Linear：** 用真实产品过程作为首屏证据，而不是用抽象功能卡解释产品。
- **OpenRouter：** 保留模型、价格和可用性的透明度。
- **Vercel：** 每项能力必须与使用结果相连。
- **Stripe：** 信息按“主张 → 证据 → 风险处理 → 接入”逐级推进。
- **Raycast：** 动效用于解释产品行为，不用于持续装饰。
- **Anthropic / Claude：** 使用克制排版、大留白和可信叙事。

这些原则只用于提炼结构和体验，不复制具体网站的组件、插画或布局。

- Focus 使用 Customer 的 `0 0 0 3px rgb(15 180 119 / 13%)`。
- 不把所有内容放进圆角卡片；只有真实交互边界才使用面板。

## 首页结构

首页采用以下证据阶梯：

```text
01 请求剖面       TokenFlux 如何做出选择？
02 模型市场快照   TokenFlux 有哪些可选择的模型？
03 故障切换回放   主路由失败时会发生什么？
04 统一接口       接入 TokenFlux 有多简单？
05 最终行动区     用户下一步去哪里？
```

每一章节承担独立职责。完整的多模型价格、上下文、延迟和可用率表只出现在“模型市场快照”；Hero 默认只展示评分、排名、角色和所选主路由摘要，候选指标仅在 Hover、Focus 或触摸展开时作为解释信息出现；故障回放只展示当前主备切换结果。

### 全局页面框架

- 保留品牌、全局搜索、首页、模型、排行榜、价格、文档、服务状态和控制台入口。
- 品牌始终显示完整的 TokenFlux 名称，移动端不得只剩无法识别的字母图标。
- 桌面导航高度约 `72px`。
- 当前路由使用一层浅绿状态，不同时叠加胶囊、粗底线和阴影。
- 全局搜索继续支持命令面板、键盘导航和 Escape 关闭。
- 导航下方保留 `32px` 高的低强调提示条，固定文案为：`交互原型 · 页面数据与路由结果均为 Mock`。
- 提示条不使用 Emerald 实心背景，不与主导航或 Hero 争夺层级。

### 1. 首屏「请求剖面」

#### 空间结构

首屏不做左右产品卡分栏。桌面结构为：

1. 上方使用约八列宽度承载主张、说明和双 CTA。
2. 策略按钮紧邻请求剖面，属于产品状态，不作为独立营销卡。
3. 下方十二列宽度完整展开请求链。
4. 主路由与备用路径在首屏底部形成结果闭环。

在 `1440 × 900` 视口中，用户无需滚动即可看到：

- 主标题。
- 支持文案。
- 两个 CTA。
- 三种策略。
- 完整五步请求链。
- 当前主路由。
- 至少一个备用路径。
- 当前选择理由。

主文案固定为：

```text
每次请求，
都知道为什么这样选。
```

支持文案固定为：

> 统一接入多个模型，根据性能、价格与可用性，为每次请求选择更合适的路径。

CTA：

- `创建 API Key` → `#/console/keys`
- `浏览全部模型` → `#/models`

#### 五步请求链

```text
API 入口 → 协议归一化 → 候选评分 → 主路由 → 备用路径
```

- **API 入口：** 固定显示 `POST /v1/chat/completions` 和 Mock 请求 ID `REQ_8F2A`。
- **协议归一化：** 固定显示 `schema: openai.chat`、`messages: 1`、`stream: true`，表达请求已转换为统一内部契约。
- **候选评分：** 同时展示 Claude 3.7 Sonnet、Gemini 2.5 Pro、DeepSeek V3 和 GPT-4.1；默认只显示模型、归一化分数、排名和角色。
- **主路由：** 展示当前策略的最终模型、归一化得分、首 Token p50 和示例可用率。
- **备用路径：** 展示一个明确备用模型和备用角色。

路径、节点和分叉是结构本身，不再套进大型控制台卡片。普通状态使用中性线，当前路径使用 Emerald，备用路径使用中性虚线。

#### 策略与确定性数据

首页不得维护第二套模型指标。价格、上下文、延迟和可用率全部读取 v7 既有 `detailCatalog`，并以它作为唯一数据源：

| ID | 模型 | 输入 / 1M | 输出 / 1M | 上下文 | 首 Token p50 | 示例可用率 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `claude-3.7` | Claude 3.7 Sonnet | $3.00 | $15.00 | 200K | 612ms | 99.98% |
| `gpt-4.1` | GPT-4.1 | $2.00 | $8.00 | 1M | 780ms | 99.99% |
| `gemini-2.5` | Gemini 2.5 Pro | $1.25 | $10.00 | 1M | 425ms | 99.96% |
| `deepseek-v3` | DeepSeek V3 | $0.27 | $1.10 | 128K | 520ms | 99.94% |
| `qwen-3` | Qwen 3 235B | $0.55 | $2.20 | 128K | 560ms | 99.93% |
| `claude-haiku` | Claude 3.5 Haiku | $0.80 | $4.00 | 200K | 310ms | 99.99% |

首页请求剖面使用 `claude-3.7`、`gemini-2.5`、`deepseek-v3`、`gpt-4.1`；模型市场快照使用表内全部六个 ID。

策略按钮为可聚焦按钮组：

- 平衡
- 速度优先
- 成本优先

初始状态为“平衡”。评分范围固定为 `0–100`，数值越高越优。每种策略使用固定 Mock 结果：

| 策略 | Claude | Gemini | DeepSeek | GPT-4.1 | 主路由 | 备用路径 | 备用角色 |
| --- | ---: | ---: | ---: | ---: | --- | --- | --- |
| 平衡 | 94 | 89 | 84 | 86 | Claude 3.7 | Gemini 2.5 | 低延迟备用 |
| 速度优先 | 82 | 96 | 87 | 74 | Gemini 2.5 | DeepSeek V3 | 快速备用 |
| 成本优先 | 71 | 86 | 98 | 63 | DeepSeek V3 | Gemini 2.5 | 低延迟备用 |

这些分数明确标记为 Mock 归一化评分，不声称代表生产算法或实时监控。

角色文案固定为：

- 平衡：Claude `主路由`、Gemini `低延迟备用`、DeepSeek `成本候选`、GPT-4.1 `质量候选`。
- 速度优先：Gemini `主路由`、DeepSeek `快速备用`、Claude `稳定候选`、GPT-4.1 `待命`。
- 成本优先：DeepSeek `主路由`、Gemini `低延迟备用`、Claude `质量候选`、GPT-4.1 `待命`。

选择理由固定为：

- 平衡：`综合质量、健康度、延迟与成本后的最高加权分`
- 速度优先：`当前候选中首 Token 延迟最低，并保留快速备用路径`
- 成本优先：`在健康阈值内选择当前预估成本最低的候选`

切换策略时必须在一次状态提交中同步更新：

- 四个候选分数。
- 候选得分排名标记。
- 主路由。
- 备用路径。
- 路径线状态。
- 主路由的得分、首 Token p50 和示例可用率。
- 选择理由。
- `aria-pressed` 和可访问状态。

候选数据始终可见；策略切换不是筛选，不能隐藏未选模型。
四个候选节点的位置和 DOM 顺序保持固定，只更新分数、排名标记、角色和路径状态，避免策略切换造成布局跳动。

鼠标悬停或键盘聚焦候选节点时，显示该候选既有的输入 / 输出价格、首 Token 延迟和可用率，并将三项分别标记为成本、速度和稳定性依据。纯触摸设备点击候选节点切换同一说明，按钮使用 `aria-expanded`；一次只展开一个候选。该说明不得引入另一套无法解释的评分数字。

### 2. 模型市场快照

第二屏承担“选择范围和透明度”的证据，不再重复完整决策过程。

- 使用一张横向数据平面，而不是模型卡片墙。
- 固定展示 Claude 3.7 Sonnet、GPT-4.1、Gemini 2.5 Pro、DeepSeek V3、Qwen 3 235B 和 Claude 3.5 Haiku。
- 列包括模型与供应商、上下文、输入价、输出价、示例 p50 延迟和示例可用率。
- `idle` 和 `simulating` 状态下，当前策略的主路由使用浅绿推荐行；`failed-over` 状态下，高亮切换为实际接管的备用模型。
- 点击或键盘激活模型行进入对应 `#/models/:slug`。
- 首页不复制模型目录的搜索、筛选、排序和对比控件。
- 行动入口：`查看全部模型` → `#/models`。

本章节只证明模型与指标透明；完整发现流程留给二级页面。

### 3. 故障切换回放

第三屏是第二个品牌记忆点，使用一条清楚的请求时间线表达韧性。

初始状态：

- 当前策略的主路由处于正常状态。
- 当前策略的备用路径已建立但未接管。
- 按钮文案为 `模拟上游超时`。

用户点击后：

1. 主路由进入“超时”状态。
2. 当前 Emerald 主线路收束为警告状态。
3. 备用线路接管并成为新的活动路径。
4. 结果区更新为备用模型、最终延迟和切换原因。
5. 按钮变为 `重新播放`。

状态机固定为：

```text
首次回放：idle → simulating → failed-over
重新播放：failed-over → idle → simulating → failed-over
策略切换或离开首页：任意状态 → idle
```

- 回放不使用随机值。备用基础延迟读取 `detailCatalog`，Mock 路由切换开销固定为 `126ms`，最终首 Token 延迟等于两者之和。

| 策略 | 超时主路由 | 接管备用 | 备用基础延迟 | 切换开销 | 最终延迟 | 固定切换原因 |
| --- | --- | --- | ---: | ---: | ---: | --- |
| 平衡 | Claude 3.7 Sonnet | Gemini 2.5 Pro | 425ms | 126ms | 551ms | Claude 3.7 Sonnet 超时，已切换至低延迟备用 Gemini 2.5 Pro |
| 速度优先 | Gemini 2.5 Pro | DeepSeek V3 | 520ms | 126ms | 646ms | Gemini 2.5 Pro 超时，已切换至快速备用 DeepSeek V3 |
| 成本优先 | DeepSeek V3 | Gemini 2.5 Pro | 425ms | 126ms | 551ms | DeepSeek V3 超时，已切换至低延迟备用 Gemini 2.5 Pro |

- 切换策略时立即取消未完成回放并恢复 `idle`。
- 离开首页时清理所有尚未完成的单次动画计时器。
- `simulating` 时按钮文案固定为 `正在切换…` 并禁用，避免重复触发并发状态。
- 结果通过 `aria-live="polite"` 通知辅助技术。
- 点击 `重新播放` 时先同步恢复 `idle`，再启动下一次 `simulating`，不保留上一次超时状态。

### 4. 统一接口

第四屏只证明接入简单，不构建 Playground。

- 展示 `curl`、JavaScript、Python 三个代码标签。
- 默认展示 JavaScript。
- 使用既有 `https://api.example.com/v1` Mock 地址，避免伪造生产域名。
- 首页标签使用独立属性 `[data-home-code-language]`，不得复用模型详情的 `[data-code-language]` 或文档页的 `[data-doc-language]`。
- 三份示例直接读取 v7 的 `codeExamples`，通过 `codeExamples[language].replace(/__MODEL__/g, 'anthropic/claude-3.7-sonnet')` 生成首页文本；不得修改 `codeExamples` 原对象，也不得另写一套请求格式。
- 提供复制按钮。成功 Toast 固定为标题 `已复制`、说明 `内容已写入剪贴板`；失败时继续使用标题 `复制内容` 并展示可手动复制的完整文本。
- 代码窗口可以使用 Customer 强文字色作为紧凑中性背景，但不得扩展为深色整屏营销区。
- 行动入口：
  - `创建 API Key` → `#/console/keys`
  - `阅读接入文档` → `#/docs`

### 5. 最终行动区

页面以大留白和固定主张 `从一个接口开始，让每次选择都有依据。` 收尾：

- 主行动：`创建 API Key`

## 状态模型与数据流

不重构 v7 的路由、搜索、筛选、对比、详情、估算器、排行榜、Key、弹窗或代码语言状态。首页只新增一个隔离状态对象：

```javascript
var homeState = {
  routingStrategy: 'balanced',
  failoverState: 'idle',
  homeCodeLanguage: 'javascript',
  expandedCandidateId: '',
  failoverTimerIds: []
}
```

`routingResult` 不作为第二份可变状态保存，而是每次通过 `routingScenarios[homeState.routingStrategy]` 派生。模型指标统一读取既有 `detailCatalog`。

每次 `#/home` 模板完成渲染时必须先清理旧计时器，再把整个 `homeState` 重置为以上初始值，然后渲染默认平衡策略并播放一次进入动画。直接加载首页、站内导航返回首页和浏览器后退回首页必须得到相同初始状态。离开首页时清理全部首页计时器并把故障状态恢复为 `idle`。

首页策略数据集中存放在 `routingScenarios` 中。交互数据流为：

```text
用户选择策略
  → 清理故障回放并更新 homeState.routingStrategy
  → 读取固定 routingScenarios
  → 读取 detailCatalog 指标并派生 routingResult
  → 同步渲染候选评分、路径、结果、市场高亮和可访问状态
```

故障回放数据流为：

```text
用户触发回放
  → homeState.failoverState = simulating
  → 当前主路由标记超时
  → 当前备用路径接管
  → homeState.failoverState = failed-over
  → 更新结果与 aria-live
```

禁止通过多个互不关联的事件处理器分别修改线路、数字和文案。首页代码不得改写 v7 既有的 `selectedModels`、`activeAbility`、`activeContext`、`mockKeys`、`pendingKey`、`lastFocusedElement` 或其他深层页面状态。

### 旧首页逻辑替换边界

新首页必须替换或退役 v7 的以下首页专用逻辑，禁止旧、新两套策略状态同时存在：

- `activeRouteStrategy`
- `routeStrategyData`
- `renderHomeRouteDecision`
- `startHomeRouteAnimation`
- `stopHomeRouteAnimation`
- `setupCurrentPage()` 中重置旧策略并调用旧首页渲染的分支

允许在 `setupCurrentPage()` 和共享事件委托中替换上述首页分支，以接入 `homeState`、`renderRequestAnatomy`、故障回放和 `[data-home-code-language]`。模型目录、详情、排行榜、价格、文档、Console 和 API Key 的相邻分支必须原样保留。

## 动效

### 首屏进入

每次完成 `#/home` 渲染后播放一次：

1. API 入口出现。
2. 线路进入协议归一化。
3. 候选评分依次稳定。
4. 主路由亮起。
5. 备用路径建立。

总时长控制在 `650–850ms`，完成后静止。

### 策略切换

- 数字、背景、边框和路径状态在 `180–240ms` 内同步变化。
- 不移动整体布局，不造成内容跳动。

### 故障回放

- 单次回放为 `500–700ms`。
- 不使用循环流光、自动轮播、持续脉冲、漂浮或滚动驱动动画。

### Reduced Motion

`prefers-reduced-motion: reduce` 下：

- 首页直接显示最终路由状态。
- 策略切换立即完成。
- 故障回放保留状态变化，但取消线路运动。
- 所有非必要过渡关闭。

## 响应式

### `>= 1200px`

- 横向五步请求剖面。
- 完整候选评分和主、备用结果。
- 模型市场保持完整列。

### `960–1199px`

- 主张仍位于请求剖面上方。
- API 入口和归一化可保持横向。
- 候选评分、主路由和备用路径允许转为两行。
- 不压缩为不可读的小型控制台。

### `768–959px`

- 请求剖面改为上下结构。
- 候选评分保持完整字段。
- 市场数据使用紧凑表格或结构化行。
- CTA 可以并排，但必须满足点击目标尺寸。

### `< 768px`

- Hero 首个移动视口优先展示完整品牌、标题、主 CTA、当前主路由和一个备用结果的紧凑摘要。
- 次 CTA 保留为至少 `44px` 高的轻量文字链接，不与主 CTA 使用两块同等重量的实心按钮。
- 完整请求剖面紧接摘要向下展开为纵向五步时间线，允许五步内容延伸到首个视口以下。
- 保留完整 TokenFlux 品牌名。
- 表格改为结构化行卡，但价格、上下文、状态等字段不得消失。
- 主要点击目标至少 `44px`。
- 不使用 `9px` 业务文字。
- `375px`、`390px` 和手机横屏均不得出现页面级横向溢出。

## 可访问性

- 策略按钮使用 `aria-pressed` 暴露当前选择。
- 候选评分使用可理解的表格或列表语义。
- 代码标签使用 `tablist`、`tab` 和 `tabpanel` 语义。
- 故障回放结果和复制结果使用 `aria-live="polite"`。
- 模型行支持 Tab 聚焦，Enter 或 Space 进入详情。
- Escape 关闭命令搜索、移动菜单和弹窗。
- 弹窗关闭后恢复触发按钮焦点。
- 所有键盘可操作元素显示 Customer Focus。
- 图标按钮具有清楚的 `aria-label`。
- 颜色不能作为主路由、备用路径、超时或选中状态的唯一表达。

## 数据与异常处理

- 所有数据来自内存 Mock。
- 不新增 `fetch`、XHR、Axios、WebSocket、SSE 或其他网络请求。
- 不使用 Local Storage、IndexedDB 或 Cookie 保存伪生产状态。
- 不使用 `setInterval`。
- 单次动画只允许使用可清理的短时计时器。
- 缺少动画节点时直接显示最终状态，不抛出阻断性异常。
- 重复触发故障回放时忽略后续点击，直到当前回放结束。
- 剪贴板不可用或复制失败时，使用 Toast 显示待复制内容。
- 无效模型详情与其他未知 Hash 一样规范化到 `#/home`，保持现有路由行为。
