# OpenRouter V6 Demo 精修设计（2026-08-30）

## 状态

本设计已由用户确认。实施以 V6 为唯一视觉基线，停止继续 V7「路由决策」与 V8「请求剖面」方向。用户随后提供 AI Tokens Flux 首页参考图，并明确要求把其中的环境光视觉语言加入 V6；本补充决策只吸收其柔和多向光晕与中央聚焦感，不复制参考站内容或功能。

## 背景

V6 已形成用户认可的核心组合：OpenRouter 式居中价值表达、API 向五个 Provider 分流的路由轨迹、Customer 浅色 Emerald 色系、非对称能力矩阵、热门模型账本，以及作为唯一深色表面的 Quickstart。后续 V7、V8 虽增强了产品证据，但改变了 V6 的大气结构和视觉重心。

本轮不重新设计页面，只修正 V6 在首屏比例、章节节奏、卡片对齐、平板留白、移动端路由表达和细节可读性上的不足，并在 Hero 背景增加一层克制的静态环境光晕。

## 设计决策

采用 **A「V6 原版精修」并吸收少量 C「产品证据增强」**：

- 约 15% 的视觉调整，不改变页面结构与产品叙事。
- 产品证据仅通过主次路由层级、状态点、现有路由表和数据界面的精度体现。
- 不增加 V7/V8 式大型请求面板、复杂状态机或新的内容章节。
- 参考图只贡献“中心保持清晰、左侧冷色、右侧暖色、左下 Emerald 回声”的宽幅环境光构图；颜色必须由现有 Customer token 派生，不形成独立品牌色板。

- 最终预览使用新的语义化文件名；`.superpowers/` 下的 Demo 文件不得提交。

## 目标

1. 保留用户认可的 V6 视觉识别，不让页面重新变成另一套方案。
2. 桌面首页比当前 V6 缩短约 12%–15%，同时保留大气留白。
3. 桌面 Hero 标题最多两行；平板能力卡不依赖固定高度撑开；移动端能读懂 API 到多 Provider 的分流关系。
4. 提升小字号、数据列、按钮落点和代码窗口的视觉完成度。
5. 保持 Customer 色系、所有路由、交互、Mock 数据与二三级页面完全不变。

## 硬约束

- 不修改 `web/customer/`、`web/openrouter/`、后端、数据库或生产配置。
- 不新增、删除或改变任何路由、Hash 别名、导航目标、按钮行为、状态转换或数据来源。
- 不增加 Chat Playground、真实 API 请求、`fetch`、XHR、Axios、应用 WebSocket、SSE、远程字体或远程图片。
- 不增加新色值、品牌色、Provider 专属颜色、暗色主题、全站渐变体系或资产颜色。Hero 可使用由现有 `--surface-1`、`--info`、`--warning`、`--accent` 与透明度混合派生的单层静态环境光晕。
- 继续复用 V6 已映射的 Customer 背景、表面、文字、边框、Emerald、语义状态色、阴影和圆角。
- 深色表面仅允许出现在现有 Quickstart 与代码窗口。
- 保留全部现有用户可见文案和 Mock 数值。
- 不添加循环轮播、漂浮节点、动态数字、Marquee 或纯装饰动画。

## 变更边界

### 可修改

- V6 后置 Customer 覆盖层中的首页 scoped CSS：`.premium-home`、`.premium-*`、`.route-*`、`.signal-*`、`.capability-*`、`.ledger-*`、`.quickstart-*`。
- 全局 Header 仅允许移动端尺寸、间距和对齐的 CSS 微调，不改变 DOM、ID、状态或目标。
- 首页现有 DOM 只允许由 CSS 重新排版；不新增、删除或改写首页文案与控件。

### 必须冻结

- `<template id="page-models">` 起的全部二级、三级页面模板逐字冻结。
- 全部 JavaScript 逐字冻结。
- 全局 Header、命令搜索、对比栏、创建 Key 弹窗和移动菜单中的 ID、控件与 `data-route` 冻结。
- `#/home`、`#/models`、`#/rankings`、`#/pricing`、`#/docs`、`#/console`、`#/console/keys`、八个模型详情、兼容别名和未知 Hash 回退行为冻结。
- 模型搜索、筛选、排序、列表/网格、最多三个模型对比、详情标签、估算器、代码切换、复制、排行榜周期、Docs 锚点、Mock Key、命令搜索、键盘操作、焦点陷阱与恢复、移动菜单和路由状态重置冻结。

## 首页视觉设计

### 1. 顶部导航

- 桌面导航保持 V6 的顺序、宽度关系和浅绿激活态。
- 移动端搜索入口从当前 40px 空白感按钮收敛为与菜单一致的 `44×44px` 图标按钮。
- 搜索、菜单和品牌保持原有可访问名称、点击行为和焦点顺序。
- 不新增公告条、Mega Menu 或额外 CTA。

### 2. Hero

- 保留居中 Overline、主标题、副标题和双 CTA 的顺序。
- 在现有网格与路由轨迹之后、Hero 文案之前增加静态环境光层：中心维持明亮留白，左侧为极淡冷色光晕，右侧为极淡暖色光晕，左下以 Emerald 形成弱回声；边缘柔化、中心对比不降低。
- 环境光只能通过既有 Customer token 与 `color-mix()` 派生，不写新的 Hex/RGB/HSL/OKLCH 色值；不改变根 token，不扩散到能力区、模型区、Quickstart 或二三级页面。
- 环境光不响应鼠标、不漂移、不循环，不与路由连接动画竞争；移动端降低强度，保证标题、CTA、五节点和四项 Signal 的可读性与首屏合同。
- 桌面 Hero 目标高度约 600px，较当前 670px 收紧约 10%；文案底部预留同步减少。
- 桌面标题使用约 60–68px 的响应式区间，保持黑色主句与深绿强调句，最多两行。
- 副标题保持两行以内；双 CTA 的宽度、间距和肩线一致。
- 不把 Hero 改成左右分栏，不添加大型 SaaS 外卡或新的产品面板。

### 3. 路由轨迹

- 保留 API 原点、Anthropic、OpenAI、Google、DeepSeek、Qwen 五个节点及现有分叉语义。
- API 原点是最强节点；五个 Provider 为次级节点。现有中心路径（Google 节点）作为静态 Demo 的样例主路径，通过线宽、透明度和状态点形成轻微提示；其余四条路径保持同一弱层级。该处理只服务于构图，不表达真实 Provider 偏好或改变任何逻辑。
- 不新增价格、延迟等新文案或 Mock 数值；产品证据来自现有路由结构、现有状态色和能力区路由表。
- 桌面网格背景进一步降噪，保证标题始终是首要视觉信息。
- 进入 `#/home` 后连接动画只播放一次，目标时长 700–850ms，完成后静止。

### 4. 平台指标

- 保留四项指标、顺序、数值与文案。
- 桌面单项高度目标为 88–96px，减少当前 104px 的空白。
- 数值继续使用等宽字体，说明文字提高可读性，并统一点、数值和标签的基线。
- 移动端继续为 2×2，不使用横向滚动或隐藏字段。

### 5. 能力矩阵

- 桌面继续采用 5/7 + 7/5 的两行非对称布局，四项能力和入口目标不变。
- 卡片标题、正文、行动按钮和内部 Mock 界面建立统一基线。
- 正文统一为 14px；内部表头不低于 10px，关键名称与数值使用 11–12px，避免 9–11px 信息在大卡片中显得过弱。
- 桌面卡片目标高度约 330–350px，不使用无意义的固定空白。
- 平板端保持 2×2，但高度由内容驱动；内部接口、路由表、价格条和 Key 策略面板自然接续文案。
- Hover 只增加 Customer 既有边框清晰度、轻阴影和最多 2px 上移。

### 6. 热门模型账本

- 保留四个模型、顺序、价格、上下文、增长数值和详情路由。
- 继续采用桌面四列、平板两列、移动单列。
- 统一模型名、Provider、价格与增长数值的行列对齐，降低增长数值悬空感。
- 不增加新的增长周期文案，不改变现有 Mock 数值或颜色语义。

### 7. Quickstart

- 继续作为全页唯一的大面积深色区域。
- 桌面左右比例约为 42/58，代码窗口略强于说明区；收紧区块外部留白与内部 padding。
- 保留现有 Python 代码、复制按钮、双 CTA 和目标路由。
- 代码窗口层级通过标题栏、代码行距、边框和留白改善，不增加语法颜色。

## 响应式设计

| 视口 | 设计要求 |
| --- | --- |
| `>=1180px` | 完整五节点路由树；5/7 + 7/5 能力布局；标题最多两行；首页较 V6 缩短约 12%–15%。 |
| `768–1179px` | 能力区稳定 2×2；卡片内容驱动高度；模型账本 2×2；内部数据界面保持可读。 |
| `<768px` | Hero、双 CTA、路由图顺序不变；CTA 全宽；指标 2×2；能力区、模型和 Quickstart 单列。 |
| `<=420px` | 五个 Provider 使用紧凑 3+2 视觉排列，不再只显示 Google；允许弱化 Provider 全称，但保留五个字母节点和完整分流含义。 |
| `844×390` 横屏 | 降低 Hero 垂直占用，导航和 CTA 不裁切，不产生横向溢出。 |

移动端验收视口 `390×844` 必须完整显示品牌、标题、说明、主 CTA、次 CTA 和路由核心结果。所有主要点击目标至少 `44×44px`，页面最小支持宽度为 320px。

## 动效与可访问性

- 同一时间仅允许路由连接作为主要运动焦点。
- 卡片和按钮过渡保持 160–180ms，不移动布局。
- `prefers-reduced-motion: reduce` 下路由轨迹立即显示最终状态，关闭非必要位移与平滑滚动。
- 保留全部现有 `aria-*`、语义角色、键盘进入、Esc 关闭、方向键切换、焦点陷阱和焦点恢复。
- 颜色不能成为唯一状态信息；现有文本、图标和结构继续承担语义。

## 数据流与异常降级

- 数据继续全部来自 V6 文件内的 Mock 数据，不读取后端或浏览器持久化状态。
- `data-route` 与 Hash 路由继续作为唯一导航入口。
- 缺少动画节点或浏览器关闭动画时，首页直接呈现完整静态结构，不抛异常。
- 复制失败继续使用 V6 现有 Toast 降级，不修改错误处理。
- 未知 Hash 继续规范化到 `#/home`。

## 验证与验收

### 静态隔离

- 输出文件与 V6 基线比较，除允许的首页/响应式 CSS 外不得出现模板或脚本变化。
- 对 `<template id="page-models">` 至脚本结束计算或比较内容，必须与 V6 基线一致。
- `data-route`、ID、路由表、模型 slug、别名和用户可见文案集合必须保持一致。
- `fetch`、XHR、Axios、WebSocket、EventSource、SSE 与 Playground 检查结果为零。

### 浏览器验证

- 只使用新建临时、禁用扩展的隔离浏览器 Profile；不得连接、导航或关闭用户真实 Edge Profile。
- 检查 `1440×900`、`1180×820`、`768×1024`、`390×844`、`375×812` 和 `844×390`。
- 所有视口无页面级横向溢出、裁切、标题孤字或不可见操作区。
- Reduced Motion 下首页直接进入最终静态状态。
- 控制台无新增异常、错误日志或 404；应用异步网络请求为零。

### 功能回归

- 验证全部静态路由、八个模型详情、兼容别名与未知路由。
- 验证首页 CTA、四项能力入口、热门模型与 Quickstart。
- 验证模型搜索、筛选、排序、视图切换、最多三个模型对比和焦点恢复。
- 验证详情标签、方向键、估算器、代码标签和复制。
- 验证排行榜周期、Docs 锚点、Mock Key 创建/搜索、命令搜索、移动菜单、键盘与 Overlay 焦点恢复。
- 对首页、Pricing、模型详情和 Console 检查计算颜色，确认仍为 Customer 浅色 Emerald，深色只存在于现有 Quickstart/代码表面。

## 非目标

- 不实现正式 React 主题。
- 不修改 `web/openrouter/` 或 `web/customer/`。
- 不增加新页面、企业销售流程、真实账户、真实 Key、支付、聊天、请求发送或持久化。
- 不复制参考图中的 Claude Code / OpenAI Codex 名称、产品 Logo、操作系统图标、语言/登录控件、售后群卡片或其业务文案。
- 不清理 V6 顶部被后置 Customer 规则覆盖的早期 CSS；避免级联变化扩大本轮范围。
- 不修改 Docker、CI、生产发布或任何生产环境。
