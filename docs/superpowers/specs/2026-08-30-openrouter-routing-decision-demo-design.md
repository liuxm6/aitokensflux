# OpenRouter 主题「路由决策台」Demo 视觉升级设计（2026-08-30）

## 背景

现有 `openrouter-customer-premium-v6.html` 已完成 OpenRouter 式的大空间结构、Customer Emerald 色系、二级与三级页面、Mock 数据和主要交互，但首页仍有明显的通用 SaaS 模板感：居中大标题、装饰性路线、四格指标、四张近似同构的能力卡和四张等宽模型条目。

本轮不是继续微调阴影和间距，而是把首页的核心视觉从“连接模型的装饰图”升级为“展示一次请求如何完成选路的真实产品现场”。用户已从三个视觉方向中选择 **A「路由决策台」**。

本轮仍然只修改交互 Demo，不修改 `web/customer/` 或正式 `web/openrouter/` 主题代码。

## Design Read

面向开发者与技术采购者的 AI API 网关首页，以清楚、可信的模型选择依据为核心，用 OpenRouter 的大尺度信息结构、Kiro 式精密产品细节和 Customer 的浅色 Emerald 系统建立高级感。

设计参数：

- `DESIGN_VARIANCE: 7 / 10`
- `MOTION_INTENSITY: 4 / 10`
- `VISUAL_DENSITY: 4 / 10`

## 已确认的设计决策

- 采用非对称「路由决策台」Hero，不再使用居中标题加五个漂浮供应商节点。
- 路由选择必须展示可读的候选模型、延迟、预估成本、健康状态、主路由、备用路径和选择理由。
- 四项能力不再表现为四张同构 Bento 卡，而是组织成三段连续产品叙事。
- 热门模型改为单一模型账本，所有价格和性能字段按列对齐。
- 首页保持 Customer 的温和浅色基底；深色只用于代码窗口，不再使用整块深色营销 CTA。
- 保留一小段 Emerald 请求路径作为首屏到下一章节的连接，但不做贯穿全页的装饰线。
- 保留现有首页 CTA、四项能力入口、热门模型详情入口、全局搜索、移动菜单和所有二级、三级页面与 Mock 交互。
- 不加入 Chat Playground、真实请求发送、真实 API 调用或数据持久化。

## 视觉基线

### 色彩

只使用 Customer 已有色值和语义：

- 营销页底色：`#fbfbf9`
- 工作台底色：`#f4f6f8`
- 主面板：`#ffffff`
- 次级面板：`#f8fafb`
- 最弱表面：`#fbfcfd`
- 主文字：`#101828`
- 强文字与代码区：`#07090d`
- 辅助文字：`#667085`
- 弱辅助文字：`#98a2b3`
- 普通边框：`#e4e7ec`
- 强边框：`#d9dee6`
- 品牌绿：`#0fb477`
- 品牌绿 Hover：`#0aa668`
- 浅绿背景：`#ecfdf3`
- 浅绿边框：`#abefc6`
- 深绿文字：`#067647`

原型 CSS 直接使用 `--customer-*` 语义变量；不再以 `--accent-soft` 表示深绿文字，也不维护含义相反的二次别名。

不引入紫色、青色、霓虹、彩色渐变、玻璃拟态、环境光斑或暗色主题。供应商已有品牌资产可保留其既有颜色，但不得演变成新的页面主色。

### 排版

- 正文使用 Customer 系统中文字体栈：`-apple-system`、`BlinkMacSystemFont`、`Segoe UI`、`PingFang SC`、`Hiragino Sans GB`、`Microsoft YaHei` 等。
- API 字段、请求 ID、价格、延迟和状态数据使用等宽字体。
- Hero 中文标题字距约 `-0.03em`，不再使用 `-0.055em` 的挤压效果。
- 正文不小于 `14px`，主要说明为 `16–17px / 1.65`。
- 产品面板中的辅助信息不小于 `11px`。
- 仅英文 API 字段和缩写使用较宽字距；中文小标题不使用装饰性全大写节奏。
- 所有数字使用等宽或 `tabular-nums`。

### 形状与材质

- 普通面板圆角 `14px`，大型章节容器最多 `18px`，控件 `9–10px`。
- 静态面板使用 `1px` 边框和 `0 1px 2px rgb(16 24 40 / 4%)` 的轻阴影。
- Hover 只允许边框变为浅绿、上移 `2px` 和 Customer Hover 阴影。
- Focus 使用 `0 0 0 3px rgb(15 180 119 / 13%)`。
- 不为每个章节重复绿色顶线、悬浮胶囊或装饰性 eyebrow。

## 页面结构

### 1. 顶部导航与 Demo 提示

- 保留品牌、搜索、首页、模型、排行榜、价格、文档、服务状态和控制台入口。
- 导航继续复用现有路由和事件处理，不修改目的地或可见功能。
- 桌面导航高度约 `72–80px`，降低后台工具栏感；当前路由只使用一层浅绿状态，不同时叠加明显胶囊和粗底线。
- 搜索保持紧凑命令入口，桌面宽度约 `190–220px`。
- Demo 提示条压缩为低强调说明层，不与品牌导航争夺视觉层级。
- `<= 1080px` 时搜索自动靠右；`<= 800px` 时收为 `40px` 图标按钮。
- 移动端必须保留可识别的品牌标记、搜索和菜单，所有点击目标至少 `44px`。

### 2. 非对称 Hero

桌面使用约 `5 / 7` 的非对称布局：

- 左侧为产品主张、说明和双 CTA。
- 右侧为路由决策台，并允许视觉表面向容器右缘延展。
- Hero 主内容宽度控制在约 `1200–1240px`，不把正文铺满 1440px。

左侧内容：

- 功能性标识：`OpenAI-compatible routing` 或实际 API 入口说明，不使用两侧装饰线。
- 标题保持“一个接口，连接所有模型”，控制在两行以内。
- 副标题说明“比较价格、性能和可用性，根据策略自动选择主路由与备用路径”。
- 主 CTA：`创建 API Key` → `#/console/keys`。
- 次 CTA：`发现模型` → `#/models`。

### 3. 路由决策台

决策台不是静态插画，而是可读、可交互的 Mock 产品界面，包含：

- 请求 ID 与 API 路径。
- 当前选路策略：平衡、速度优先、成本优先。
- 至少三个候选模型或供应商。
- 候选模型和热门模型使用可识别的供应商图标或既有品牌资产，不再统一使用绿色首字母方块；原型资产必须内联或随文件提供，不产生外部资源请求。
- 每行显示模型、供应商、首 Token 延迟、预估成本、健康状态和角色。
- 明确标识一个主路由和至少一个备用路径。
- 底部解释当前选择理由，例如“综合延迟、成本和健康度后的最低加权分”。
- 一段很短的 Emerald 请求路径从入口连接到选中行，并向下延伸到证据条；它表达真实状态，不承担全页装饰。

Mock 策略交互：

- `平衡`、`速度优先`、`成本优先` 为带组标签的可聚焦按钮组，使用 `aria-pressed` 或等价可访问状态暴露当前选择。
- 切换策略时只更新主路由、备用角色、选择理由和相关强调，不发送请求、不改变路由。
- 所有候选行始终可见，避免把交互误解为筛选或隐藏数据。
- 键盘可使用 Tab 聚焦策略按钮，Enter 或 Space 激活。
- 初始策略为 `平衡`。

### 4. 路由证据条

Hero 底边直接承接一个连续容器，不再放独立四格营销卡：

- `40+` 模型提供商。
- `300+` 可用模型；如果现有 Demo 数据不足以支持精确数量，可使用更保守且明确为 Mock 的文案。
- `425ms` 当前示例最佳首 Token 延迟。
- `99.98%` 示例 30 天路由可用率。

每项使用 `20–24px` 等宽数值和 `12–13px` 标签，内部用细分隔线组织。所有数据继续明确属于 Mock Demo，不伪装为生产实时指标。

### 5. 三段连续产品叙事

四项现有能力和原有目的地全部保留，但不再使用四张同构卡。

#### 5.1 统一请求格式

- 全宽浅色章节，左侧说明“一套请求格式覆盖主流模型”，右侧为可读的请求契约或模型适配带。
- 明确展示 `POST /v1/chat/completions`、模型标识和供应商适配关系。
- 唯一行动入口：`浏览模型` → `#/models`。
- 不使用四个看起来可点击但实际只读的模型按钮。

#### 5.2 路由与成本

- 桌面使用约 `7 / 5` 两栏，不给两栏套完全相同的卡片结构。
- 主栏展示真实路由比较表：供应商、延迟、健康状态、主路由或备用角色。
- 次栏展示对齐的模型价格与性能比较，不使用含义不明的进度条。
- 路由行动入口：`查看路由表现` → `#/rankings`。
- 成本行动入口：`比较价格` → `#/pricing`。

#### 5.3 Key 策略与预算

- 使用宽幅策略面板，展示 Key 名称、模型范围、月度预算、到期时间和数据策略。
- 所有字段为只读 Mock，不表现为可切换开关。
- 唯一行动入口：`管理 API Keys` → `#/console/keys`。

### 6. 热门模型账本

- 四个现有热门模型和三级详情路由保持不变。
- 使用一个统一白色账本容器，不再使用四张等宽模型卡。
- 桌面列包括：模型与供应商、上下文、输入价格、输出价格、示例 p50 延迟、示例可用率。
- 表头约 `40px`，数据行约 `56–60px`，数字右对齐。
- 行 Hover 使用最弱表面色和 Emerald 左侧指示线。
- 删除没有解释口径的 `+18%` 等数字；若保留趋势，必须明确写为“近 7 天调用量”。
- 每一行可聚焦，Enter 进入对应模型详情。
- 移动端可以改为紧凑行卡，但价格、上下文和状态字段不得消失。

### 7. 快速接入

- 整体章节保持浅色 Customer 表面，结束页面时不突然切换为整块深色营销区。
- 左侧保留“一次集成，随时切换模型”、创建 Key 和查看文档入口。
- 右侧代码窗口使用全页唯一的深色中性表面，形成克制反差。
- 代码窗口需明确区分外层、标题栏和代码区；复制按钮至少 `44px` 高并有可见 Focus。
- 保留 OpenAI SDK 示例和复制反馈，不加入请求输入、发送按钮或 Playground。

## 动效

- 每次完成 `#/home` 渲染时播放一次请求选路动画，返回首页时允许再次播放。
- 顺序为：请求入口出现 → 细线进入决策台 → 候选行依次显现 → 主路由获得浅绿背景和左侧 Emerald 细线。
- 总时长控制在 `650–850ms`，完成后静止。
- 策略切换使用 `140–180ms` 的背景、边框和文本状态过渡，不移动布局。
- 能力章节和模型账本只使用 Hover 与 Focus 反馈，不做滚动驱动的复杂动画。
- 不使用循环流光、持续漂浮、脉冲光球或自动切换策略。
- `prefers-reduced-motion: reduce` 下直接显示最终路由状态，关闭所有非必要动画。

## 响应式

### `>= 1200px`

- Hero 为 `5 / 7`。
- 路由决策台展示完整列。
- 路由与成本章节为 `7 / 5`。
- 模型账本保持完整表格。

### `960–1199px`

- Hero 可保持较紧凑的双栏，但标题和决策台不能互相挤压。
- 如果有效内容宽度不足，Hero 提前切为上下结构，不强行保留双栏。
- 证据条保持四列或稳定的 `2 × 2`，取决于实际列宽。

### `768–959px`

- Hero 固定为上下结构，文案在上、决策台在下。
- 证据条为 `2 × 2`。
- 三段产品叙事全部单列，但内部数据仍按清楚的行列排布。
- 热门模型使用紧凑账本或两列字段行，不产生横向滚动。

### `< 768px`

- 标题约 `40–44px`，不得出现单字孤行。
- 双 CTA 全宽。
- 决策台至少保留三个候选模型；不得像旧版一样只显示一个 Google 节点。
- 候选行首行显示模型和角色，第二行显示延迟、成本和健康状态；不隐藏业务字段。
- 产品章节和热门模型为单列。
- `375px`、`390px` 和手机横屏均不得出现页面级横向溢出。

## 保留的页面、路由与交互

以下现有功能必须保持：

- `#/home`
- `#/models`
- 动态模型详情 `#/models/:slug`
- `#/rankings`
- `#/pricing`
- `#/docs`
- `#/console`
- `#/console/keys`
- 全局命令搜索和 Escape 关闭。
- 模型搜索、提供商/能力/上下文筛选、排序、视图切换和最多三个模型对比。
- 成本估算、排行榜周期切换、Mock Key 创建与搜索。
- 复制反馈、键盘进入模型详情、弹窗焦点恢复和移动菜单。
- 未知 Hash 规范化到 `#/home`。

`page-models` 起的二级、三级模板内容和现有事件逻辑本轮冻结；只允许全局导航、共享色彩变量或无行为变化的基础排版修正影响它们。不得改变其路由、字段、数据、控件或功能。

## 数据与异常处理

- 所有首页数据继续来自内存 Mock，不调用后端。
- 不新增 `fetch`、XHR、Axios、WebSocket、SSE 或其他网络请求。
- 策略切换只更新本地展示状态。
- 缺少动画节点时直接显示最终状态，不抛异常。
- 复制失败时继续使用现有 Toast 展示待复制内容。
- 页面必须声明内联 favicon，避免首次加载 `/favicon.ico` 产生 404。
