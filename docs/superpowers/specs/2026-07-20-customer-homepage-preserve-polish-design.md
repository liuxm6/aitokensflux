# Customer 首页保留式精修设计

## 设计判断

- 页面类型：面向 AI 编程用户的品牌型落地页
- 改造模式：保留式精修
- 视觉语言：高冲击动态模型品牌、浅色中性色、青橙氛围渐变、绿色单一主色
- 实现基础：现有 React 19、TypeScript、Rsbuild 与原生 CSS
- 设计参数：
  - `DESIGN_VARIANCE: 7`
  - `MOTION_INTENSITY: 6`
  - `VISUAL_DENSITY: 3`

## 目标

保留用户认可的原版首屏，不重新设计品牌识别。通过排版、节奏、材质、状态和响应式细节，使首页从“功能完整”提升到“成熟、克制、有品牌感”，同时保留 Gemini、Grok、无障碍和现有业务能力。

## 当前审查

### 品牌资产

- 主色：`#0fb477`
- 主文字：近黑色 `#0b0c0e`
- 页面基底：暖白 `#fbfbf9`
- Hero 资产：Claude、OpenAI、Grok、Gemini 官方风格图标和动态品牌文字
- 品牌标识：aitokensflux 彩色图形与字标
- 圆角体系：控件约 9-15px，卡片约 14-18px，弹窗 22px

### 信息架构

1. Hero
2. 售后群福利
3. 核心能力
4. 模型费率
5. 套餐与按量余额
6. 注册 CTA
7. 支持渠道
8. FAQ
9. Footer

路由、锚点、API、登录判断、充值、套餐和支付流程保持不变。

### 保留模式

- “輕鬆上手”短标题
- Claude、Codex、Grok、Gemini 动态轮播
- 青橙左右渐变和绿色主色
- macOS、Windows、Linux 平台图标
- “配置文檔 / 立即使用”双 CTA
- Hero 内售后群福利卡
- 四列轻量能力说明
- 黑色注册 CTA 作为页面唯一强反差区块

### 需要优化

- 导航与 Hero 内容的比例和对齐精度
- Hero 背景层次、渐变边缘和文字清晰度
- 售后群福利卡的边框、阴影和交互反馈
- 多个区块连续使用胶囊标签与居中标题造成的模板化节奏
- 模型费率表固定高度导致数据少时空白过多
- 无套餐时套餐区留白过大，按量入口不够聚焦
- 黑色 CTA 与上下浅色区块的过渡较生硬
- 支持渠道、FAQ 和 Footer 的视觉权重偏弱
- 375-900px 中间断点的间距和字号需要统一校准

## 设计方案

### 1. Hero

- 不改变 DOM 顺序、文案和模型轮播逻辑。
- 保持居中 Kinetic-Type Hero，这是用户认可且与产品匹配的品牌资产。
- 将 Hero 高度改为稳定的动态视口高度策略，保留首屏完整显示标题、模型、CTA 和福利卡。
- 收紧导航与主标题之间的无效空白，同时保证标题不超过两行。
- 降低大面积渐变的浑浊感，增加中心白场，确保模型文字始终是视觉主角。
- 统一 CTA 的边框、阴影、按压反馈和单行标签。
- 福利卡继续位于 Hero 内，宽度保持 720px 上限；优化高光边框和绿色调阴影，不使用通用玻璃拟态。

### 2. 核心能力

- 保留四列轻量分隔布局，不改成卡片阵列。
- 减少上方胶囊标签的视觉权重，标题作为主要入口。
- 调整图标、标题、正文之间的基线和间距。
- 桌面继续四列；平板使用 2x2；移动端单列并用稀疏分隔线组织。
- 不新增虚构数据、插图或说明。

### 3. 模型费率

- 保留 Claude、Codex、Grok、Gemini 标签和费率字段。
- 面板宽度和圆角保持现有体系，边框与阴影更克制。
- 表格高度改为按行数自适应并设置最大高度，数据少时不再出现大块空白，数据多时仍可滚动。
- 表头继续 sticky，数字继续使用等宽字体。
- 当前标签、悬停行和服务状态链接统一使用绿色语义。
- 681-900px 继续使用分层布局，防止标签和状态区横向溢出。

### 4. 套餐与按量余额

- 保留所有套餐、空状态和按量充值逻辑。
- 有套餐时保持套餐卡网格。
- 无套餐时压缩空状态高度，将按量服务作为该区块的主要内容。
- “按量服务”不再孤立漂浮，改为与充值卡形成明确的标题和内容关系。
- 充值卡减少说明文字的视觉噪声，突出自定义金额和立即充值。

### 5. 黑色 CTA

- 保留黑色 CTA，作为全页唯一的主题反差，避免新增第二个深色区块。
- 缩短上下外部留白，增强与套餐区和支持区的连续性。
- 保留双按钮，但统一主要意图：注册为主，配置文档为次。
- 使用近黑而非纯黑，保持品牌页面的层次。

### 6. 支持渠道

- 保留五个渠道和所有外链。
- 保持桌面横向布局，减少相同白卡造成的模板感：通过内容密度、图标底色和文字权重区分，而不是增加装饰。
- 平板采用 3+2，移动端单列。
- 卡片 hover 只使用轻微位移、边框和阴影反馈。

### 7. FAQ 与 Footer

- FAQ 保持原生 details/summary 和现有功能。
- 增加问题行的点击高度、标题权重和展开状态区分。
- Footer 提高 Logo、栏目标题和版权信息的可读性，但不增加新栏目。
- 删除不必要的视觉空白，不改变链接和法律信息。

## 动效

- 模型轮播继续作为主要自动动效，用于展示提供商覆盖范围。
- Hero 左右氛围光继续缓慢呼吸，但降低饱和和位移幅度。
- 福利卡、CTA、费率标签和支持渠道只使用有反馈意义的 hover/active 动效。
- 不增加滚动劫持、磁性按钮、视差或全页连续动画。
- 所有自动动效继续支持 `prefers-reduced-motion`。

## 响应式

- 检查宽度：375、390、700、768、900、1024、1440。
- Hero 标题最多两行，模型品牌不可被裁切。
- CTA 标签不得换行。
- 福利卡在移动端改为两列内容加整行操作按钮。
- 能力区在 768px 以下明确折叠。
- 模型费率标签允许横向滚动，但页面本身不得横向溢出。
- 支持渠道和 Footer 在移动端保持单列可扫读。

## 可访问性与性能

- 保留 Skip Link、路由焦点、键盘菜单、弹窗焦点循环和 reduced-motion。
- 保持按钮、链接和 FAQ 点击目标至少 44px。
- 不新增第三方依赖、图片请求或大型动效库。
- 只动画 `transform` 和 `opacity`。
- 页面保持浅色主题，这是现有品牌约束，不新增暗色模式。
- 页面可见文案不得包含 em dash 或 en dash。

## 不变范围

- 不修改首页文案含义和品牌 Logo。
- 不修改路由、锚点、API、表单字段、充值、套餐或支付逻辑。
- 不删除 Claude、Codex、Grok、Gemini。
- 不修改 Dashboard、认证页和其他 Customer 页面布局。
- 不引入新设计系统、字体包、图片或动效依赖。

## 验收标准

- 原版 Hero 视觉识别保持不变，首屏完整显示所有核心元素。
- 下方区块不再连续重复同一种“胶囊 + 居中标题”节奏。
- 模型费率在少量数据时不出现大块空白。
- 无套餐时按量充值成为套餐区的明确主内容。
- 375-1440px 无页面横向溢出。
- 所有现有功能、链接和交互保持可用。
- Customer 测试、类型检查、构建、格式检查通过。
- Go 全量测试通过。
- Playwright 检查无页面级 JavaScript 错误。
